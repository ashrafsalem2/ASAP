# System setup

Every setting the installation has is on one page, gathered from what each module declares.

That is the whole point of declaring them. A setting cannot exist in the code without a name, an explanation, a type, a default and a permission — and because the setup screen is built from those same declarations, it cannot exist without appearing here either. There is no hidden configuration to be told about by whoever happens to remember it, and an extension's settings arrive on the same page under the extension's own heading.

## Following the default, and being set

These are shown as different states because they behave differently. A setting that has never been touched follows the default, and follows it again if the default changes in a later version. A setting explicitly set to the same text does not. Nothing else on the screen would ever reveal which one you had.

Use "use the default" to go back, rather than typing the default in.

## Settings that lock

Some settings describe how existing figures were calculated rather than what you would prefer — the costing method is the clearest case. Once entries have been posted they can no longer be changed, and the refusal says so. That is not the system being awkward: changing one would leave every figure already on the books meaning something it never did.

## Scope

Most settings are set for the company. Some can be narrowed — to a branch, or to a user — where varying them is the point. A discount ceiling should vary by shop; a costing method must not.
